# Shared production contract

Read this alongside the selected folder's START_HERE.md and director_to_claude.json. A complete folder is a production brief, not permission to publish. The latest explicit owner instruction wins over older channel guidance. Never borrow Episode 003's paid allowance.

## Responsibilities and scope

Astra supplies the finished editorial work: researched narrative, exact wording, claim mapping, shot decisions, canonical prompts, visual references, thumbnail concepts and intended Shorts. Claude implements it and checks the resulting media. There is no assigned Claude script-challenge round. If implementation reveals an actual factual contradiction, missing dependency or impossible layout, isolate the affected item and return concrete evidence and a proposed fix to Astra; continue unrelated safe work.

Use the current root pipeline and assets without silently changing the narrator, character, palette or image model. Never touch active Episode 003 or earlier episode media. Folder ordering is not a publication schedule. Use the folder's descriptive production slug in episodes/ unless that slug already exists; inspect an existing folder rather than overwriting it. Assign any numeric publication identifier only from the current project state.

## Launch and spending

1. Verify the package's completion/review status and content hashes. Read current AGENTS.md and relevant lessons. Run the supplied package validator and current pipeline checks on the installed episode.
2. Inventory existing episode outputs and job IDs before creating work. Recover completed requests; never duplicate an unknown submission.
3. Check current Higgsfield and ElevenLabs availability, price and balance. Quote the exact core image count, dedicated thumbnail backgrounds, chapter characters and a bounded repair allowance. Present one episode quote for owner approval. The preparation task spent zero.
4. Once authorized, execute pilot, inspection, remaining batches, voice, graphics, edit, thumbnails, captions and three Shorts. Successful gates authorize continuation within the approved scope; do not end with another preflight report.
5. Actual cost and authorized ceilings are separate. A failed batch with a shared cause stops further dependent spending. A new model, larger allowance, publication or new scope requires the appropriate owner/director decision.

## Installation and implementation

Copy the selected episode inputs into episodes/<production_slug>/, preserving the development package as the signed source. Store build logs, staged media, hashes, job IDs, voice takes and reports inside that episode. Generate missing directories locally. Use native script.txt and claims.md, the supplied scene_plan.json, visual_assets.json and prompt plan. If the current pipeline's prompt schema differs, adapt the transport fields only; compare the final submitted prompt and reference roles byte for byte with the approved canonical text and report any mismatch before spending.

Use explicit source roles: a new location anchor uses the season style reference for drawing style only, never its architecture; a returning view uses only the exact accepted parent for that location. Upload the accepted local parent and bind episode, scene, SHA-256 and media ID. Do not use a scene ID from another episode or a stale generation job as the parent. Never generate the Visitor within a background.

## Image production and quality

Nano Banana Pro, 2K, 16:9 remains the season model. Use the actual current model identifier confirmed by the connector; no automatic fallback. Generate the named pilot anchors first, including the hardest period setting, character interaction and thumbnail concept. Inspect every result at native/full size before acceptance, including parent-child continuity side by side. A contact sheet is navigation, not acceptance evidence.

After the pilot passes, process the remaining location families in dependency order and small reviewable batches. Each paid request has one intended image and one narrative purpose. Prompting reduces preventable failure but cannot certify the output. Reject anatomy errors, unrequested cast, incorrect buildings/clothes, text artifacts, continuity drift, wrong time of day and mismatched action.

Graphs, captions, maps, verified lettering and evidence diagrams are local graphic work, never image-model pseudo-writing. A schematic must say it is a schematic and must not impersonate an archival scan. Factual source labels use the historical record's date, not the publication date of a modern book.

Pose/library files are inspected before use. Retired phone poses and modern devices are banned. Full-body poses need a floor and plausible scale; object inserts use no pose or an offset close-up. Follow WARDROBE_POLICY.md and the selected episode's wardrobe_spec.json. The owner authorizes researched episode-specific traditional clothing while preserving the Visitor's identity. Use private pose variants and the native episode pose registry, never change the shared library. The pirate hat is mandatory; China, Japan and Korea need distinct period-appropriate outfits. Check the same wardrobe in the video, thumbnails and Shorts.

## Voice, pacing and edit

Use the locked Amir voice and season model from channel/voice.md and config. Validate availability rather than silently switching. Generate by chapter, preserve takes, apply episode-specific pronunciations without changing unrelated words, and listen to every chapter. ASR is a locator for possible errors, not a listening certificate.

Native script contains the narration; research notes and prompts are never spoken. Captions retain correct historical spelling, even if a phonetic voice alias is used. Measure real duration before completing the main image batch: target 10–12 minutes and minimum 10. Do not stretch speed, add silent padding or fabricate material to hit duration. A substantive duration problem returns to Astra with the measured reading rate.

Build shots to the aligned speech, with eased motion and held reactions, no template transitions. Keep source notes and cards within the specified safe regions. Review every composite at output resolution. Use appropriate licensed/current channel music and only sounds that fit what is shown; absence of a suitable effect is preferable to an anachronistic cue. No paid replacement sound without the episode allowance covering it.

## Packaging

Create all three supplied thumbnail designs, using genuine generated period backgrounds and the approved Visitor library. A layout mock-up or placeholder is not a finished thumbnail. Keep the promised subject visible at 160 and 320 pixels wide, and inspect the full-resolution export for artifacts, crop edges and halos. Judge head size by the visible head, not the PNG canvas. Keep the face, headline and key object clear of corner rounding and duration overlays. The selected lead is specified in the episode folder; Claude does not ask the owner to choose routinely.

Use the supplied title and description, verified sources, concise relevant tags, chapter headings and pinned comment. Derive chapter timestamps from the actual final cut. Refresh exact-title clearance and current upload specifications before upload; do not treat a research date as permanent clearance. No fabricated search-volume, CTR or virality promise. Optional public copy need not discuss the production tools; record actual provenance internally and assess mandatory platform disclosure truthfully against the current question and rules.

## Final review and delivery

Run native factual/script checks, pose checks, caption audit, final technical checks and export hash manifests. Review each image and composite, then watch and listen to the entire final video in order, including cuts, cards, effects and the ending. Frame samples cannot replace continuous playback; unavailable listening remains open. Target approximately -14 LUFS with true peak at or below -1 dBTP.

Cut the specified Shorts from the selected master using actual word alignment; keep each story self-contained, retain necessary dates/hedges and recompose for portrait framing. Inspect and listen to all three, including caption safe areas and end cards.

Put one clearly selected video, lead thumbnail, alternate thumbnails, captions, upload copy and three Shorts into REVIEW <production_slug> at the project root. Include an owner-readable README, exact paths and hashes, measured duration/audio figures, coverage evidence and any real open defect. Never label a package ready to upload while known errors or required reviews remain unresolved. Preserve candidates and all superseded assets in build/, not mixed into the owner review folder. No automatic publication.

## Learning

For every confirmed failure record the affected asset, expected/observed behavior, evidence, root cause or uncertainty, chosen repair, cost and preventive check. Read the relevant channel lessons at launch, before spend and before delivery. Record acceptance rate, repeat faults and repair spend without claiming improvement until measured. Carry only relevant lessons into individual prompts. Future performance review uses the channel's own data; no autonomous polling or publishing is created by this brief.
